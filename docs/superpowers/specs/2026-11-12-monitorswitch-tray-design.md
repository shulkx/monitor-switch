# MonitorSwitch 托盘软件设计

日期：2026-11-12
状态：待审阅

## 1. 目标

用一个轻量、好看的托盘软件代替显示器背后的物理按键和厂商的大体积软件（如 Dell Display and Peripheral Manager），在几台电脑共用的显示器上一键切换输入源。

成功标准：

- 按一个快捷键或在托盘面板上点一下，显示器在 2 秒内切到目标输入，并有屏幕提示确认。
- 面板上能看出每个接口接的是哪台设备：本机自动识别，装了本软件的另一台电脑通过局域网自动识别，其余由用户命名。
- 同一套代码在 Windows、macOS、Linux 上构建；Windows 版经过真机验证。
- Windows 安装包小于 10 MB，不需要管理员权限，不需要额外安装运行时（使用系统自带的 WebView2）。

## 2. 范围

### 包含

- 托盘图标、托盘面板（磁贴）、右键菜单。
- 切换时的屏幕提示（OSD）。
- 支持所有响应 DDC/CI 的外接显示器，可同时管理多台。
- 每个接口的名称和直达快捷键；一个"来回切换"快捷键。
- 本机接口自动识别；局域网互相发现另一台电脑；未命名接口被切到时的新设备提示。
- 学习接口：用于显示器报告的接口和标准值对不上的情况。
- 开机自启、只运行一份。
- Windows、macOS、Linux 三平台构建。

### 不包含

- 亮度、对比度、音量等其他显示器设置。
- 通过网络远程控制另一台电脑，或接受网络发来的切换命令。
- 插拔 USB 设备时自动切换。
- 厂商私有协议（例如部分 LG 型号要求的另一套寻址方式）。这类显示器尽力而为，不保证。

## 3. 界面

视觉稿：Claude Design 画布"MonitorSwitch 托盘界面方案"中的 E1 和 E2 两张（B 方案的深色磁贴，加 D 方案的屏幕提示）。<https://claude.ai/artifact/LiLyugzzun3sVNBvE8DLpt>

### 3.1 托盘图标

- 图标：显示器线条图标。
- 悬停提示：每台显示器一行，"显示器型号 · 接口名（接口）"，例如"Dell U2723QE · 公司笔记本（USB-C）"。
- 左键：打开或收起托盘面板。
- 右键：系统原生菜单。有多台显示器时，每台一个子菜单；接口列表里当前那个打勾；最后是"设置"和"退出"。

### 3.2 托盘面板

- 深色圆角面板，固定宽度 352 px，贴近托盘位置弹出，失去焦点自动收起。
- 有多台显示器时，顶部是显示器切换标签；只有一台时显示型号。
- 显示器名下面一行写"正在显示 ××"，右侧是设置按钮。
- 2 列磁贴：
  - 每个接口一块：图标、接口名、接口类型。当前接口整块填充主题色。
  - 本机接口带"本机"标签；局域网发现的电脑带绿点和"在线"标签；被检测到但还没命名的接口带"新设备"标签。
  - 未命名接口用虚线边框。
  - 最后一块固定是"来回切换"，显示它的快捷键。
- 每次打开面板时立即重新读一次所有显示器的当前输入。
- 显示器无响应时，那台的磁贴区域显示"显示器没响应，检查显示器菜单里的 DDC/CI 是否开启"，其余显示器照常可用。

### 3.3 屏幕提示（OSD）

- 屏幕中央偏上的深色圆角卡片：设备图标、"已切换到"或"正在切换到"、设备名、"接口 · 显示器型号"。
- 鼠标可穿透，不抢焦点，1.5 秒后淡出。
- 可在设置中关闭。
- 显示时机见 5.2。

### 3.4 新设备提示

- 托盘附近的小卡片："××显示器切到了 HDMI 2 / 这个接口还没有名字，是新接上的设备吗？"
- 按钮："起个名字"打开设置并定位到该接口；"忽略"让该接口不再提示。
- 10 秒后自动消失。

### 3.5 设置窗口

- 显示器下拉框：选中要编辑的显示器，旁边写"共 N 台"。
- 接口卡片，每个接口一张：
  - 图标。
  - 标签行，如"DP · 本机，自动识别"、"USB-C · 局域网里发现了它"、"HDMI · 还没起名字"。
  - 名称输入框。
  - 快捷键按钮：点击后进入录制，按下组合键即保存，按 Esc 取消，按 Backspace 清空。
- "接口列表不对？学习接口"入口。
- 开关和设置：
  - 来回切换：在哪两个接口之间切（两个下拉框），以及它的快捷键。
  - 切换时显示屏幕提示（默认开）。
  - 在局域网里自动识别另一台电脑（默认开）。
  - 开机时启动（默认开）。
  - 高级：按显示器关闭"自动读取接口列表"（见 6.4）。
- 所有更改即时保存，没有"确定"按钮。

### 3.6 学习接口窗口

- 第 1 步：提示用户用显示器按钮切到要登记的接口。窗口打开期间每秒读一次当前输入值，并实时显示，如"读到当前接口值 0x12"。
- 第 2 步：选择"这是哪个口"（标准接口名列表，加"其他"），填写设备名称。
- 后备方案"逐个试一遍"，用于读不到值的显示器：
  - 列出候选值。来源依次是：显示器报告的接口列表、标准值 0x0F/0x10/0x11/0x12/0x1B，以及用户手动输入的十六进制值。
  - 每个值一个"试一下"按钮，点击即发送切换命令。
  - 画面切过去后，用户点"是这个"确认。
- "保存"后，该值作为这个接口记入设置，以后切换都用它。

## 4. 技术选型

- Tauri 2：后端 Rust（当前环境 rustc 1.99），界面为 TypeScript + Vite，不用 UI 框架，以控制体积。
- DDC/CI：
  - Windows：直接调用系统的 dxva2 接口，并用 QueryDisplayConfig 把显示器和连接口对应起来。不用 `ddc-hi`，因为它在 Windows 上默认同时启用 NVIDIA 后端，同一台显示器会出现两次，而且它的 Windows 后端不提供 EDID。
  - macOS 和 Linux：`ddc-hi` crate。Linux 下走 i2c-dev，macOS 下走 IOAVService（Apple Silicon）或 IOFramebuffer（Intel）。
- Tauri 插件：
  - `global-shortcut`：全局快捷键。
  - `autostart`：开机自启。
  - `single-instance`：只运行一份。
  - `positioner`：把面板定位到托盘附近。
- 每个平台各写一个小模块，用于本机连接类型检测：
  - Windows：`windows` crate 调用 QueryDisplayConfig。
  - macOS：IOKit。
  - Linux：读取 `/sys/class/drm`。

## 5. 架构

### 5.1 模块

```
monitor-switch/
  src-tauri/src/
    main.rs             应用启动、托盘、窗口、模块之间的连线
    ddc/backend.rs      DisplayBackend trait
    platform/           各平台的 DisplayBackend 实现（Windows 直接调系统接口，macOS / Linux 用 ddc-hi）
    ddc/caps.rs         解析接口列表字符串，标准值与接口名对照表
    monitor_service.rs  后台工作线程：命令队列、轮询、缓存、事件
    local_port/mod.rs   本机接在哪个口；mod.rs 下按平台分 windows.rs / macos.rs / linux.rs
    peers.rs            局域网发现：广播、接收、过期
    config.rs           设置的读写与迁移
    hotkeys.rs          快捷键注册与冲突上报
    commands.rs         暴露给界面的 Tauri 命令
  src/
    flyout/   托盘面板
    osd/      屏幕提示
    toast/    新设备提示
    settings/ 设置与学习接口
    shared/   设计变量（颜色、圆角、字号）与图标
```

各模块的职责：

- `DisplayBackend`：只做 4 件事。`list()` 列出显示器（id、型号、EDID 标识），`read_input(id)` 读当前输入，`set_input(id, value)` 切换输入，`capabilities(id)` 读接口列表。单元测试用假实现替换它。
- `MonitorService`：独占 `DisplayBackend`，在一个线程上串行执行所有 DDC 操作。
  - 对外接口：`refresh()`、`switch(monitor, value)`、`probe(monitor, value)`（学习接口里"试一下"用）。
  - 对外事件：`state-changed`、`input-changed{monitor, from, to, cause}`、`monitor-error`。
- `LocalPort`：输入是系统报告的本机显示连接（每台显示器的 EDID 标识，以及连接类型 HDMI / DP / 其他），加上本机是否为笔记本（有无电池）。输出是每台显示器上"本机接口值"的猜测。用户在设置里手动指定后，以用户指定为准。
- `Peers`：定期广播本机状态，维护在线对端表。只影响显示，不触发任何操作。
- `Config`：负责 JSON 设置文件，见 5.4。

### 5.2 关键流程

**切换**（由快捷键、磁贴或右键菜单触发）：

1. 目标接口如果不是本机接口，并且"显示屏幕提示"开启，就先在本机屏幕显示 OSD"正在切换到 ××"，停留 600 ms 后再发命令。切走之后本机画面就看不见了，所以提示必须在切换之前出现。
2. `MonitorService` 发送 `set_input`。失败时每隔 50 ms 重试，最多 3 次。
3. 1.5 秒后读回当前输入：
   - 与目标一致：发出 `input-changed`，cause 为 `user`。
   - 不一致：在面板和托盘提示里标出"切换可能没有生效"。
4. 目标接口如果就是本机接口，确认切换成功后显示 OSD"已切换到 本机名"。

**轮询**：

- 每 4 秒读一次每台显示器的当前输入。
- 系统锁屏、显示器休眠或程序正在执行切换时暂停。
- 值变化且不是本程序刚刚触发的，发出 `input-changed`，cause 为 `external`。

**另一台电脑上的提示**：本机轮询发现输入变成了本机接口（cause 为 `external`，即在另一台电脑上触发了切换），就在本机显示 OSD"已切换到 本机名"。

**新设备提示**：`input-changed` 的目标接口同时满足下面 4 个条件时，弹出新设备提示：

- 没有名字；
- 不是本机接口；
- 不是在线对端所在的接口；
- 没有被"忽略"过。

**来回切换快捷键**：作用于每一台配置了"来回切换接口对"的显示器。每台各自判断：当前是对里的第一个就切到第二个，否则切到第一个。这样两台显示器一起做 KVM 时可以同步切换。

**接口快捷键**：只作用于所属的那台显示器。

### 5.3 本机接口识别规则

对每台显示器，用 EDID 标识把它和本机的显示连接对应起来，然后按顺序判断：

1. 用户在设置中手动指定过本机接口：用指定值。
2. 连接类型是 HDMI：如果显示器的接口列表里只有一个 HDMI 值，就用它；有多个则需要用户确认（取最小值作为默认）。
3. 连接类型是 DP（USB-C 的 DP 替代模式通常也报告为 DP）：
   - 本机是笔记本，且接口列表里有 USB-C 值（0x1B）：判定为 USB-C。
   - 否则：取 DP 值（0x0F，没有则 0x10）。
4. 以上都判断不了：标记为"未识别"，在设置里提示用户指定。

### 5.4 设置文件

位置：

| 平台 | 路径 |
|---|---|
| Windows | `%APPDATA%\MonitorSwitch\config.json` |
| macOS | `~/Library/Application Support/MonitorSwitch/config.json` |
| Linux | `~/.config/MonitorSwitch/config.json` |

格式：

```json
{
  "version": 1,
  "showOsd": true,
  "lanDiscovery": true,
  "autostart": true,
  "toggleHotkey": "Ctrl+Alt+M",
  "monitors": {
    "DEL-426A-ABC1234": {
      "label": "Dell U2723QE",
      "readCapabilities": true,
      "capsReadPending": false,
      "cachedCapabilities": "<显示器报告的接口列表原文>",
      "localPortOverride": null,
      "togglePair": [15, 27],
      "ports": {
        "15": { "name": "我的主机", "hotkey": "Ctrl+Alt+1" },
        "27": { "name": "公司笔记本", "hotkey": "Ctrl+Alt+2" },
        "17": { "name": null, "hotkey": null, "ignored": false }
      },
      "learnedPorts": { "18": "HDMI 2" }
    }
  }
}
```

- 显示器键由 EDID 生成：厂商代码-产品代码-序列号。取不到序列号时，用厂商代码-产品代码-型号名。
- 写入方式：先写临时文件，再改名替换，避免写到一半损坏。文件损坏时备份为 `config.bad.json`，然后用默认值启动。
- `version` 字段用于以后的格式迁移。

### 5.5 局域网发现协议

- UDP 组播，地址 `239.255.77.77:47777`，TTL 1（不出本网段）。
- 每 5 秒发送一次；收到对端消息后 15 秒内没有新消息，就视为离线。
- 消息内容（JSON，最大 2 KB）：

  ```json
  {"app":"monitorswitch","v":1,"id":"<随机实例 UUID>","name":"<电脑名>","kind":"laptop","monitors":[{"key":"DEL-426A-ABC1234","port":27}]}
  ```

- 收到的消息只用来在面板上显示对端的名字和在线状态。以下情况一律丢弃：
  - 格式不符；
  - `app` 字段不对；
  - 消息来自本机实例。
- 永远不根据网络消息执行任何操作。
- 用户给接口起的名字优先于对端名字。对端名字只在接口没有用户命名时显示，并标"在线"。

### 5.6 窗口与平台细节

- **托盘面板**：无边框、透明、置顶、不在任务栏显示；失去焦点时隐藏；位置由 positioner 插件按托盘位置计算。
- **OSD**：无边框、透明、置顶、鼠标穿透；显示在鼠标所在的屏幕上。
- **主题**：跟随定稿视觉稿，固定深色；主题色默认 #2563EB，以后可以设置。
- **macOS**：托盘即菜单栏图标；全局快捷键不需要辅助功能权限。
- **Linux**：
  - 需要 `i2c-dev` 模块，用户在 `i2c` 组里；
  - 缺少权限时在面板里给出提示和命令；
  - 托盘依赖桌面环境的 AppIndicator 支持。

## 6. 出错处理

1. **DDC 命令失败**：重试 3 次后在对应显示器上显示错误，其余显示器照常工作。不弹模态框。
2. **快捷键冲突**：注册失败时，设置里对应快捷键按钮标红，显示"已被其他程序占用"，并且不保存。
3. **显示器断开、重新连接**：收到系统显示变化通知后重新枚举显示器；断开的显示器在面板中显示"未连接"并保留设置。
4. **读取接口列表的风险**：少数显示器在 Windows 下读取接口列表时会触发系统蓝屏，这是 Windows 本身的问题。缓解措施：
   - 每台显示器只读一次，结果缓存在设置文件中；
   - 读取前把该显示器的 `capsReadPending` 设为 true 并立即保存，读完改回 false。启动时如果发现它还是 true，说明上次读取时崩溃了，自动把该显示器的 `readCapabilities` 关掉，并提示用户改用学习接口；
   - 用户也可以在高级设置里手动关闭。
5. **局域网不通**（防火墙、VPN）：静默降级为手动命名，设置里该开关下方显示"未发现其他电脑"。
6. **设置文件损坏**：见 5.4。
7. **重复启动**：single-instance 插件把已运行的实例调出来，打开它的面板。

## 9. 风险与已知限制

- **macOS Apple Silicon**：DDC 走的是苹果未公开的接口，有开发者报告通过 USB-C 连接时不够稳定；部分 Mac 的内置 HDMI 口不支持 DDC。
- **非标准显示器**：部分型号（例如一些 LG）读不到输入值，或只接受厂商私有指令。学习接口里的"逐个试"能覆盖一部分，私有指令不支持。
- **非当前输入**：有的显示器在非当前输入上不接受 DDC 命令。在这样的显示器上，只有正在被显示的那台电脑能发起切换。
- **公司电脑**：可能禁止安装未签名程序，或拦截组播。前者需要用户自行确认能否安装；后者会自动降级为手动命名。
- **本机接口判断**：判断规则是启发式的。带 USB-C 的台式机，或 HDMI 转 DP 的线材都可能误判，所以保留手动指定。
